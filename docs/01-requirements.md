# 01 需求说明

## 用户

内容团队运营：接到一个内容活动需求（主题、预算、截止时间），需要在约束内产出一份可执行的方案。

## 目标

在**不超预算、不超截止时间**的前提下完成一份方案：检索素材 → 估算成本 → 生成脚本 → 保存方案；
对每一步给出真实状态；无法完成时给出未完成原因与缺口。

## 输入

- 主题、预算（模拟单位）、截止时间（小时）；
- 合成素材库（可按标签检索，含质量档位与授权费）；
- 费用与耗时表（工具档位、服务单价、工期）；
- 候选方案目录（按质量从高到低排序，含素材组合与工序档位）。

## 交付结果

任务计划、步骤状态（成功/失败，含每次尝试）、工具结果、费用合计（预算/已用/剩余）、
已保存方案或未完成原因（含最低可行成本与缺口）。

## 范围

做的：四工具（素材检索 / 成本估算 / 脚本生成 / 方案保存）、ReAct 决策循环、步骤状态机、
失败重试与续跑、执行上限、防虚报声明核对、CLI、测试与两套证据。

不做的：真实素材平台与发布动作、线上部署、多 Agent、真实业务数据（全部为合成数据）。

## 成功标准

1. 正常完成：可行方案被保存，费用合计与预算核对一致；
2. 缺预算或截止时间：不强行规划，明确返回缺失项；
3. 工具失败：失败步骤如实记录（含重试），已成功步骤保留；
4. 预算超限：改选替代方案（12→8）；全部不可行时返回缺口；
5. 重复执行：已有方案不重复保存；
6. 加分：失败步骤续跑，只重做未成功步骤；
7. 任何情况下不得把失败步骤记为成功、不得虚报保存或完成。
