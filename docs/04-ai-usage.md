# 04 AI 使用说明

## AI 辅助内容

- 工程脚手架、四工具初版、费用引擎、ReAct 循环与 Mock 决策器初版由 AI 生成；
- 文档 01-05 与 README 由 AI 起草，人工核对事实与数字；
- 合成数据（素材、费用表、方案目录、请求集）由 AI 按题目构造。

## 个人修改与关键接管

- **费用表与参考实例对齐**：按题目「初始方案 12、替代方案 8」重算 AP-A/AP-B 的档位单价，
  并补充 AP-C（5.5）用于“无可行方案”场景；
- **步骤状态落账**：将每次工具调用（含失败）写入步骤流水，报告逐条展示状态与摘要，
  失败明确标注「结果未被记为成功」；
- **依赖校验**：脚本要求估算通过、保存要求脚本成功，防止模型跳步伪造完成；
- **续跑机制**：新增 `prior_steps` 与 resumed 跳过逻辑，实现「只重做失败步骤」的加分项。
  首版把历史失败计入重试预算，导致修复后仍直接放弃；当时改为「重试预算按本轮计算」；
- **声明核对**：修复两个误判——“已完成步骤”被当成任务完成、缺截止场景的“预算内”被误判为虚报；
- **真实模型两轮修订**：缺预算时模型仍调用估算 → 工具直接报缺失错误并要求检索后结束；
  缺截止时间时模型被“估算未通过”误导性报错驱动循环重试 → 同一修复，重跑后 2 步内正确结束。

## 验证方式

- `python3 -m unittest discover -s tests -v`：26 个测试全部通过（`examples/test-results.txt`）；
- 11 个 Mock 场景 + 11 个真实模型场景逐条核对 Trace（`examples/index.md`、`examples/real-model/index.md`）；
- 参考实例关键核对：AP-A 估算 12 超预算 2.0 → AP-B 估算 8 可行 → 脚本 S001 → 方案 P1001，
  预算剩余 2.0，步骤状态 5 成功 0 失败，声明核对通过。
